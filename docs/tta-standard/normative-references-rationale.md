# 인용 표준 채택 근거 및 예상 질의 대응

*(표준초안 §2 「인용 표준」 보충 자료 — 심의·검토용)*

본 자료는 표준초안이 규범적으로 인용하는 3건의 국제표준에 대하여, 각 인용의 근거와 본 표준과의 관계를 설명하고, 검토·심의 과정에서 제기될 수 있는 질의에 대한 대응 논거를 정리한다. 표준 본문에는 포함되지 않는 배경 설명 자료이다.

## 1. 인용 표준 요약

| 인용 표준 | 발행기관 / 판 | 본 표준에서의 활용 | 인용 성격 |
|---|---|---|---|
| Decentralized Identifiers (DIDs) v1.0 | W3C / 2022-07-19 (Recommendation) | DID 레지스트리 기반 퍼블릭키 해석 (§5.3·§5.5) | 규범적 |
| Verifiable Credentials Data Model v2.0 | W3C / 2025-05-15 (Recommendation) | 검증 가능한 위임 자격증명(VC) 방식 (§5.3.1) | 규범적 |
| RFC 3339 (Date and Time on the Internet) | IETF / 2002-07 | 유효기간 등 시각 표현 규범화 (§5.4.1) | 규범적 |

본 표준은 위 3건을 **대체하지 않으며**, 그 위에 권한위임·검증·감사 계층을 추가하는 관계에 있다.

## 2. 인용 표준별 채택 근거

### 2.1 W3C Decentralized Identifiers (DIDs) v1.0

- **개요**: 중앙 등록기관 없이 검증 가능한 분산형 식별자를 정의하는 W3C 권고안(Recommendation). DID는 DID Document로 해석(resolve)되며, 그 안의 `verificationMethod`가 공개키·검증 방법을 제공한다.
- **본 표준에서의 활용**: 위임자·에이전트·위임장 발급자의 식별자를 DID로 표현하고, 권한위임정보 및 위임장에 대한 서명 검증 시 DID로부터 해석된 공개키를 사용한다(§5.3, §5.5).
- **인용 근거**: 본 표준의 검증 절차는 "누가 서명했는가"를 신뢰 가능한 방식으로 판별해야 하며, 이를 특정 인증기관(CA)에 종속되지 않는 표준 방식으로 달성하기 위해 DID를 규범 인용한다. 자체 식별자 체계를 정의하면 상호운용성이 저해되고 국제표준과의 정합성이 약화된다.

### 2.2 W3C Verifiable Credentials Data Model v2.0

- **개요**: 발급자(issuer)가 주체(subject)에 대한 클레임을 검증 가능한 형태로 발급하고, 검증자(verifier)가 이를 확인하는 데이터 모델을 정의하는 W3C 권고안.
- **본 표준에서의 활용**: 위임장(권한위임장)의 네 가지 발급 방식 중 하나인 **검증 가능한 위임 자격증명(VC) 방식**의 데이터 구조와 서명·검증 절차 기반으로 인용한다(§5.3.1).
- **인용 근거**: 위임장은 "위임자가 에이전트에게 특정 권한을 부여했다"는 검증 가능한 클레임이며, 이는 VC 데이터 모델의 발급자–주체–검증자 구조에 정확히 대응한다. VC를 인용함으로써 기존 VC 생태계(지갑·검증기)와의 상호운용이 가능하다.

### 2.3 IETF RFC 3339 (Date and Time on the Internet: Timestamps)

- **개요**: 인터넷 프로토콜에서 날짜·시각을 표현하는 ISO 8601 기반의 프로파일. UTC 오프셋을 포함한 명확한 타임스탬프 형식(예: `2026-07-01T00:00:00Z`)을 규정한다.
- **본 표준에서의 활용**: 권한위임장의 유효기간(발효·만료 시각) 등 모든 시각 표현을 RFC 3339 형식으로 규범화한다(§5.4.1).
- **인용 근거**: 유효기간 판정은 검증의 핵심 요소이며, 시각 표현이 구현체마다 다르면 상호운용과 감사에 오류가 발생한다. RFC 3339는 시간대 모호성을 제거하고 기계 판독이 용이한 단일 형식을 제공한다.

## 3. 예상 질의 및 대응

**Q1. 이들 국제표준을 반드시 규범 인용해야 하는가? 참고 인용으로 충분하지 않은가?**
본 표준의 검증 절차(§5.5)는 DID 해석으로 얻은 공개키와 VC 구조에 직접 의존하며, 유효기간 판정은 RFC 3339 형식을 전제한다. 즉 이들 없이는 본 표준의 필수 절차를 구현할 수 없으므로 규범적(normative) 인용이 타당하다.

**Q2. DID v1.1이 아니라 v1.0을 인용한 이유는?**
DID v1.1은 인용 시점 기준 후보권고안(Candidate Recommendation, 2026-03-05) 단계로 규범 인용에 적합한 안정 단계가 아니다. 따라서 정식 권고안(Recommendation)인 v1.0을 규범 인용하고, v1.1은 부록의 비규범 참고로 다룬다.

**Q3. VC 2.0은 충분히 성숙했는가?**
VC 2.0은 2025-05-15 정식 권고안으로 확정되었으며, 본 표준은 데이터 모델(발급자–주체–검증자 구조·증명 방식)에 한정하여 인용하므로 안정성 우려가 적다.

**Q4. 시각 표현에 ISO 8601이 아닌 RFC 3339를 택한 이유는?**
RFC 3339는 ISO 8601의 상호운용 가능한 부분집합 프로파일로, 인터넷 프로토콜에서 시간대·형식 모호성을 제거한다. 블록체인·네트워크 프로토콜 환경에 더 적합하므로 RFC 3339를 규범으로 하되, 그 상위 규격인 ISO 8601과 정합한다.

**Q5. 국제표준(W3C/OIDF/DIF)은 블록체인을 선택 사항으로 두는데, 본 표준이 블록체인을 필수로 하는 것과 상충하지 않는가?**
본 표준은 DID/VC의 데이터 모델·검증 방식을 그대로 준용하되, "권한위임정보의 온체인 등록과 변조 불가능한 감사"라는 계층을 추가하는 것이다. 이는 국제표준이 열어 둔 확장점(레지스트리·상태 관리 방식의 선택)을 특정한 것으로, 표준 간 충돌이 아니라 상보 관계이다. (상위 거버넌스 표준과의 관계는 부록 「연계(family) 표준」 참조.)

**Q6. 인용표준의 정의를 그대로 쓰지 않고 본 표준에서 재정의한 용어가 있는 이유는?**
DID·VC·시각 표현 등 기존 표준에 정의된 개념은 해당 표준을 인용하고, 권한위임·위임 레지스트리·에이전트 이벤트 로그 등 본 표준 고유의 프로토콜 구성요소만 본 표준에서 정의한다. 용어별 출처는 §3(용어 정의)의 출처 표기를 따른다.

---
*비고: 표준 본문에 직접 포함하지 않는 심의 대응용 배경 자료이다. 인용 표준의 발행일·판 번호는 표준 본문 §2(인용 표준)와 일치시켜 관리한다.*
